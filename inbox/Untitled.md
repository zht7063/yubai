## 先把那条提问翻译成人话

那条评论看着乱七八糟，其实一口气糊了三件事在一起，拆开就清楚了：

1. DeepSeek 的官方 agent 应用，和把 DeepSeek 的模型接进 Codex，有什么区别？
2. 同样是把 DeepSeek 接进去，接进 Codex 和接进 Claude Code 又有什么区别？
3. 那我到底该选哪个？

要回答这三个问题，光知道“模型和 harness 是两个东西”还不够，得再往下垫一层。

## 模型是发动机，harness 是车

我更喜欢用这个比喻：模型是发动机，harness 是车。

发动机决定这台车最多能跑多快、有多省油；但底盘、变速箱、悬挂、方向盘手感，全是车厂的事。同一台发动机，装在性能车上是性能车，装在面包车上是面包车。你踩油门的感觉、过弯的信心、油耗的表现，都不会一样。

再把话说明白一点：模型不干活，harness 干活，中间还得靠一层“约定”来沟通。模型没法自己伸手去读你的文件，它只能输出一段结构化的内容，大意是“我想调用某个工具，参数是这些”；harness 收到之后，真的去执行，再把结果塞回给模型看。这一来一回，就是大家口中的 agent：模型负责想，harness 负责做，两者靠协议对齐。

所以“DeepSeek 的 agent 模型”这个说法，本身其实不太严谨。DeepSeek 提供的是模型；agent 是模型加上壳、加上工具、加上协议之后才有的东西。这种词被随口叫开，是圈内圈外割裂感最直接的来源之一。

## 三个组合，分别是什么

**组合一：DeepSeek 的官方应用（网页、App、官方 agent）。** 模型和壳都是厂商自己家的，配合最紧，什么能做什么不能做由厂商定。缺点是开箱即用，也止步于开箱即用，你没法改它干活的方式。

**组合二：Codex 接 DeepSeek 模型。** 壳是 OpenAI 那套，模型是 DeepSeek 的。这个一般要你自己动手配：把 Codex 的模型地址指向一个兼容 OpenAI 协议的服务，填上 key，选好模型名。好处是你直接拥有了 Codex 的工作流：自己看目录、读文件、改代码、跑命令、回头检查；代价是它会有点水土不服。

**组合三：Claude Code 接 DeepSeek 模型。** 同一个思路，只是壳换成了 Anthropic 那套。这条路一般要经过一个“格式兼容层”，把 Anthropic 的请求格式翻译成 DeepSeek 那边能听懂的。

## 同一个模型，换个壳怎么就像变笨了

这是最值得讲清楚的一点，因为它反直觉。原因大致有这几层：

- **工具调用的格式是给自家模型调过的。** 壳会告诉模型“我这儿有哪些工具、参数长什么样、你该怎么调用”，这套说明书写出来的时候，参考的是自家模型的脾气。换一个脾气不同的模型，它可能漏调用、参数写错、或者明明一步能做完的事绕三步。
- **系统提示词也是给自家模型写的。** 壳里塞了一大段“你该怎么干活”的规矩，什么先规划再执行、什么时候别废话直接动手。这些规矩对自家模型是校准，对别家模型可能只是噪音。
- **上下文管理策略不一样。** 什么时候压缩历史、压缩掉多少、保留哪部分，直接决定模型“记不记得住前半段”。长任务里，这一项的差距往往比模型本身的分数差距更大。
- **训练偏好不一样。** 有的模型天生习惯先把计划写出来再动手，有的习惯直接开干；有的模型特别爱用工具，有的更爱凭记忆硬答。壳是按前者的节奏设计的，遇到后者就别扭。
- **中间多了一层翻译。** 走兼容层的组合，本质是转译：转译就会丢东西，可能丢掉一点推理过程、丢掉缓存命中、丢掉某些字段。它还能用，但它是打了折的可用。

所以“把 X 模型接进 Y 壳”从来不是免费的。你换来的可能是更便宜的价格、更擅长的语言，或者某个壳好用的工作流；你付出的是适配上的损耗。这笔账划不划算，取决于你更在乎哪一头。

## 那到底要不要折腾

按人群分，我给三种建议：

- **只想把事办成的人**：用官方应用。别折腾，折腾的成本远大于省下的那点体验差异。
- **已经有顺手的壳、清楚自己想要什么的人**：值得折腾。比如你习惯了某个壳的工作流，又想让某个模型的长处补上它的短板，或者纯粹对价格敏感。但请接受它打折。
- **想搞清楚原理的人**：一定要自己折腾一次。配一遍模型地址、看一眼请求日志、感受一下同一个模型在两个壳里的差别，比看十篇“震惊瘫坐”有用得多。我自己的很多认识都是从这种笨办法里来的。

## 一个粗糙但好用的判断法

决策的时候，我会问自己四个问题：

1. **这件事需要“动手”吗？** 只是问答、写作、翻译，模型自己就够；要读写文件、跑命令、集成到项目里，就必须有壳。
2. **任务有多长？** 一轮就结束的，随便选；要跑几十轮、跨好几个小时的，把上下文管理和稳定性放在第一位，这时候壳的质量比模型分数重要。
3. **预算敏感吗？** 算总账，单价乘上消耗，别只看单价。便宜但话多、绕路的模型，未必真的省。
4. **数据敏感吗？** 你要想清楚请求都经过了谁的服务器：模型厂商、壳的厂商、还是中间的转发。

这四个问题答完，答案基本就自己浮出来了，不需要记住任何版本号。

## 最后说一句

术语不是门槛，术语是墙纸。墙纸会一直换：今天叫 agent，明天叫 workflow，后天又冒出个新词。但墙后面的四层结构不会变，模型、壳、协议、工具，谁在哪一层、谁替谁干活。想清楚这四层，所有的“震惊瘫坐”和“新一代超级大模型”都只是新闻，而不是你需要跟上的节奏。

下一期我想聊一个更实际的问题：同样一段需求，为什么有人能让 AI 一次做对，有人改十遍还在原地打转。这里面没有魔法，全是方法。
