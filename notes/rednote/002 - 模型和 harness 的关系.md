# 大白话讲模型和 Harness 的关系

上一篇我们讲了两个概念：模型是一个“续写文本”的数学函数，Harness 是套在模型外面、帮它干活的外壳。没看过的朋友可以先翻一下上一篇，这一篇会直接在它的基础上往下讲。

上一篇结尾留了一个坑，就是文章开头那条评论提问（翻译成人话以后）：

```
直接使用 DeepSeek 官方的 Agent（底层也是 DeepSeek 模型），与在 Codex 或 Claude（通常指 Claude Code 等客户端）中接入 DeepSeek 模型，这几者之间有什么区别？
```

这条评论看着乱，其实是三个问题糊在了一起，拆开就清楚了：

1.   DeepSeek 官方的 Agent，和把 DeepSeek 模型接进 Codex，有什么区别？
2.   同样是接 DeepSeek，接进 Codex 和接进 Claude Code 又有什么区别？
3.   那我到底该用哪个？

这一篇我们就用一个“发动机和汽车”的比喻，把这三个问题一个一个讲明白。

---

模型是发动机，Harness 是车。

发动机决定了这台车最多能跑多快、劲儿有多大；但是方向盘好不好握、座椅舒不舒服、过弯稳不稳、油耗高不高，这些全是车厂的事。同一台发动机，装在跑车上就是跑车，装在面包车上就是面包车，开起来的感觉完全不一样。

模型和 Harness 也是这样。模型决定了“脑子”有多聪明，Harness 决定了这个脑子能做哪些事、做事的方式顺不顺手。

那它们俩具体是怎么配合的呢？我们还是拿上一篇“写 word 文档”的例子来说。

上一篇我们说过，模型本身只会输出文字，自己是碰不到你电脑上的文件的。所以当你让 AI 帮你写一段汇报的时候，实际发生的事情大概是这样的：

1.   模型想了想，输出一段文字：“我要用‘写 word’这个工具，写入的内容是 xxx”；
2.   Harness 看到这段话，知道模型想用工具了，于是真的去打开 word，把 xxx 写进去；
3.   Harness 再把结果告诉模型：“写好了”或者“出错了，原因是 xxx”；
4.   模型看到结果，决定下一步做什么，然后继续重复上面的过程，直到任务完成。

这里有个小细节：模型说“我要用工具”的这段话，不能随便说，必须按照 Harness 规定好的格式来写，Harness 才能看得懂。这就像去餐厅点菜，你得按菜单上的名字点，说“给我来个那个红红的、辣辣的”，服务员是没法下单的。这套双方约定好的格式，就是大家常说的“协议”。

模型负责想，Harness 负责做，两边靠协议沟通，这样一来一回地干活，就是我们常听到的 **Agent（智能体）**。当然，现在的 Agent 能做的远不止这么简单的一来一回：它会自己把大任务拆成小任务、先做计划再动手，甚至好几个 Agent 分工合作。这些进阶玩法，我们后面再慢慢聊。

所以，聪明的读者应该已经发现了：评论里说的“DeepSeek 的 agent 模型”这个说法，本身就不太严谨。DeepSeek 提供的是模型（发动机），而 Agent 是模型加上 Harness（整车）之后才有的东西。

---

理解了发动机和车的关系，我们再来看评论里的三种用法，就很好理解了。

**第一种：直接用 DeepSeek 官方的 App、网页或者官方 Agent。** 这就相当于买了一台原厂整车，发动机和车身都是同一家厂子做的，配合得最好，开箱即用。缺点是，这台车怎么开、能去哪，都是厂家定好的，你没法自己改装。

**第二种：在 Codex 里接入 DeepSeek 模型。** Codex 是 OpenAI 家做的 Harness，这就相当于把 DeepSeek 的发动机拆下来，装进了 OpenAI 家的车里。这一般需要自己动手配置一下：告诉 Codex 模型在哪里（填一个模型地址），再给它一把钥匙（填一个 API key）。配好之后，你就拥有了 Codex 那一整套干活的方式：自己看目录、读文件、改代码、跑命令、回头检查，等等。（具体怎么一步步把国产模型接进 Codex 或者 Claude Code，之后我会出一篇手把手的教程，跟着做就行。）

**第三种：在 Claude Code 里接入 DeepSeek 模型。** 思路和第二种一样，只是车换成了 Anthropic 家的。不过这里经常会多一步：因为 Claude Code 和 DeepSeek 说话的“格式”不完全一样，中间常常要加一个“转接头”，把 Claude Code 的话翻译成 DeepSeek 能听懂的样子。

---

到这里，很多人会遇到一个很反直觉的情况：明明是同一个模型，换了个壳之后，怎么好像变笨了？

还是用车来理解：你把一台发动机装进别家的车里，大概率是要磨合一阵子的。具体来说，有这么几个原因：

**第一，说明书是给自家模型写的。** Harness 会告诉模型“我这里有哪些工具、每个工具怎么用”，这份说明书在写的时候，参考的是自家模型的习惯。换一个模型来读，可能就会出现忘了用工具、参数填错、或者一步能做完的事情绕三步的情况。（工具到底是怎么“交到”模型手上的，现在常听到的 MCP、Skills 这些词又是什么，我们后面会专门挑一篇来讲。）

**第二，规矩也是给自家模型定的。** Harness 里会预先塞给模型一大段“工作守则”（我们叫它系统提示词），比如“先想好计划再动手”、“别说废话直接干活”之类的。这些规矩对自家模型来说是调教好的，对别家模型来说，可能就是一堆不太合拍的要求。顺带一提，为什么同样一个意思换个说法，AI 的表现就能差很多，这背后其实就是大家常说的“提示词设计”，这个话题值得单独展开，我们之后细说。

**第三，记性管理的方式不一样。** 模型一次能“记住”的内容是有限的，聊得久了，Harness 就得把前面的对话压缩一下，挑重点留着。什么时候压缩、压缩多少、留下哪些，直接决定了模型干到后半段还记不记得前面说过什么。任务越长，这一点的影响就越大，甚至会比两个模型本身的差距还大。

>   这里说的“记性”，在 AI 圈里有个专门的名字，叫“上下文”。还有一个经常和它混在一起的概念叫“长期记忆”，比如有的 AI 能记住你上周跟它说过的话。上下文和长期记忆到底有什么区别、Harness 又是怎么帮模型“记事”的，这块内容不少，我们留到后面单独写一篇。

**第四，每个模型的脾气不一样。** 有的模型习惯先把计划列出来再动手，有的习惯直接开干；有的模型特别爱用工具，有的更喜欢凭自己的记忆硬答。车是按照某种开法设计的，换了个脾气不一样的“司机”，自然开着别扭。

**第五，转接头会漏东西。** 像第三种那样需要加转接头的情况，本质上是在做翻译，而翻译就难免会丢东西，可能是一部分思考过程，也可能是一些本来能帮你省钱的机制。它还能用，但是是“打了折”的能用。

所以我们用一句话总结：**把一个模型接进别家的 Harness，从来不是免费的。** 你换来的可能是更便宜的价格、更擅长中文的模型、或者一个更顺手的工作流程；付出的代价是磨合上的损耗。划不划算，就看你更在乎哪一头。

---

最后回到第三个问题：那我到底该用哪个？

我的建议是按人来分：

-   **只想把事情办成的人：** 直接用官方应用就好。折腾的成本，远远大于你省下来的那一点体验差异。
-   **已经有顺手的工具、知道自己想要什么的人：** 值得折腾。比如你已经习惯了某个 Harness 的工作方式，又想用某个模型的长处来补它的短板，或者单纯想省钱。但要接受它可能会打点折扣。
-   **想搞明白这里面原理的人：** 一定要自己动手折腾一次。亲手配一遍、看看同一个模型在两个壳里表现有什么不一样，比看十篇“震惊瘫坐”都有用。我自己的很多理解，也都是从这种笨办法里来的。

如果还是拿不准，我自己平时会问自己这么四个问题：

1.   **这件事需要“动手”吗？** 如果只是问答、写作、翻译，模型自己（官方聊天应用）就够了；如果要读写文件、跑命令、改项目，那就必须要有一个 Harness。
2.   **任务有多长？** 聊一两句就结束的，随便选；要来回几十轮、跑好几个小时的，优先考虑稳不稳、记性好不好，这时候“车”的质量比“发动机”的跑分更重要。
3.   **在不在乎钱？** 要算总账，不能只看单价。有的模型单价便宜，但话多、爱绕路，最后花的钱不一定少。（AI 到底按什么收费、大家常说的 token 是什么、前面第五点里那个“省钱的机制”又是怎么回事，后面我单独开一篇，带大家算算这笔账。）
4.   **在不在乎隐私？** 想清楚你的内容都会经过谁的服务器：模型厂家的、Harness 厂家的，还是中间转接头的。

这四个问题想清楚了，答案基本也就出来了，不需要记任何型号和版本号。

---

最后想多说一句：AI 圈的新词会一直换，今天叫 Agent，明天可能叫 Workflow，后天又会冒出来一个新名字。但是背后的结构其实一直没怎么变：模型负责想，Harness 负责做，两边靠协议沟通，工具负责落地。把这几层想明白，那些“震惊瘫坐”、“新一代超级大模型”就只是新闻，而不是你必须追着跑的节奏。
